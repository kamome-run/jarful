# Kusha（クシャ） 仕様・要件定義書

- 版: 1.1 (2026-09-22) — 1.1 で対象プリンター（Bluetooth Classic）と複数印刷プロトコルを追加
- 対象: Android（Chromebook 含む）/ Windows 11 デスクトップ
- 根拠記事: `SOURCES.md` を参照。本文中の `[S1]` `[S2]` `[S3]` は出典記号。

---

## 1. 目的

ADHD 傾向のある人が「先延ばし」を減らし、毎日安定してタスクをこなせるようにする
**ゲームループ型タスク管理アプリ** を提供する。

記事で示された手法 [S1][S2][S3] を、紙・付箋・レシートプリンターを持たない人でも
アプリ単体で再現でき、レシートプリンターを持つ人はそのまま連携できるようにする。

## 2. 設計原則（記事から導出）

| # | 原則 | 根拠 |
|---|------|------|
| P1 | **ループを頻繁に回す**: タスクは 2〜5 分のマイクロタスクまで分解できる。先延ばしするほど細かく分解する。 | S2, S3 |
| P2 | **強いフィードバック**: 完了の瞬間に触覚・音・視覚の三重の報酬（くしゃっと丸める→透明な瓶へ）を与える。 | S2, S3 |
| P3 | **始めやすさ**: 1 日は簡単な日課から始める。前夜に翌日分を準備し、朝は考えずに始められる。 | S3 |
| P4 | **有形性（tangible）**: タスクを「今日のチケット」として画面上の一覧から切り出し、付箋のように 1 枚ずつ扱う。物理的に印刷もできる。 | S2, S3 |
| P5 | **摩擦ゼロ**: チケットの準備は自動化（曜日別ルーチンの自動生成、一括印刷）。入力はキーボードだけで高速に完結する。 | S2, S3 |
| P6 | **全体像と次の一手**: 階層タスクを縦の長いリストではなく横並びの列（カラム）で表示し、選択したタスクの子だけを次の列に出す。 | S2, S3 |
| P7 | **柔軟性**: 次の 3〜5 個だけを決める「リフォーカス」、分解できないタスクの「時間分解」、蓄積タスクの「毎日 N 件」処理を用意する。忘れて進めても罰しない。 | S3 |

## 3. 対象プラットフォームと技術

| 項目 | 内容 |
|------|------|
| Android | Android 8.0 (API 26) 以上。スマートフォン・タブレット・**Chromebook（ChromeOS の Android ランタイム）** で動作。 |
| Windows | Windows 11 (x64)。MSI インストーラおよび実行可能 JAR を配布。 |
| 共通コード | Kotlin Multiplatform + Compose Multiplatform。ドメイン・UI・印刷ロジックを `shared` モジュールで共有。 |
| データ | 端末ローカルのみ（JSON ファイル）。アカウント不要、クラウド同期なし。 |
| 通信 | 外部との通信はサーマルプリンターへの送信（Bluetooth Classic SPP / シリアル COM / TCP 9100）のみ。テレメトリなし。 |
| ライセンス | MIT License（OSS）。 |

### 3.1 Chromebook 要件 (`[NFR-CB]`)

- `android.hardware.touchscreen` を `required="false"` とし、タッチ非搭載機でもインストール可能にする。
- ウィンドウのリサイズ・マルチウィンドウを許可する（`resizeableActivity=true`）。
- 物理キーボードとマウス/トラックパッドで全操作が可能（§8 ショートカット）。
- 幅 840dp 以上ではデスクトップと同じ 3 ペイン構成で表示する。
- 触覚フィードバックは搭載機のみ動作し、非搭載機ではエラーにならない。

## 4. 用語

| 用語 | 定義 |
|------|------|
| タスク (Task) | 階層を持つ作業項目。子タスクを持てる。ルート直下のタスクを「プロジェクト」と呼ぶこともある。 |
| マイクロタスク | 2〜5 分程度で終わる末端のタスク。 |
| チケット (Ticket) | 特定の日に「やる」と決めて切り出したタスクの 1 枚。付箋・レシート 1 枚に相当。 |
| 瓶 (Jar) | その日に完了したチケットが紙玉として溜まる透明な容器。 |
| ループ | チケット 1 枚の「開始→完了→フィードバック」の 1 サイクル。 |
| ルーチン (Routine) | 曜日ごとに繰り返す習慣。毎日自動でチケット化される。 |
| クォータ | ルーチンの一種で「N 件処理する」と数を目標にするもの。 |
| 列 (Column) | カラムビューでの 1 階層。 |

## 5. 機能要件

### FR-1 カラムビュー（階層タスクの横並び表示） [S3 P6]

- FR-1.1 ルート列に最上位タスクを表示し、タスクを選択すると **右隣の列** にその子タスクを表示する。列は階層の深さだけ右に増える（上限なし、横スクロール）。
- FR-1.2 選択したタスクのパス（パンくず）を常に表示する。
- FR-1.3 各タスク行には、タイトル、子タスク数（未完了/全体）、今日のチケット化済みマーク、完了マークを表示する。
- FR-1.4 列の見出しには親タスク名を表示し、その列全体に対して「全部を今日のチケットにする」「列を印刷する」操作を提供する。
- FR-1.5 完了済みタスクは既定で列の末尾に薄く表示し、非表示に切り替えられる。

### FR-2 タスクの作成・分解・編集 [S2 S3 P1 P5]

- FR-2.1 タスクは **1 回の入力で連続作成** できる（入力→Enter→次の入力欄が即座に開く）。
- FR-2.2 選択中のタスクの **子タスク** をショートカット 1 つで追加できる（分解）。
- FR-2.3 タスクに任意で「所要時間の目安（分）」を設定できる。既定は未設定。マイクロタスクの目安として 2〜5 分を UI で示唆する。
- FR-2.4 タスクに任意で **タイムボックス（分）** を設定できる（「10 分間掃除する」型）。タイムボックス付きチケットは実行時にカウントダウンタイマーを表示する。 [S3]
- FR-2.5 タスクの並べ替え（上下移動）、階層移動（親を変更）、名称変更、削除（子を含む）ができる。削除は取り消し（Undo）できる。
- FR-2.6 任意のタスクを「テンプレートから分解」できる: 複数行テキストを貼り付けると各行が子タスクになる。
- FR-2.7 タスクに「先延ばし度」は保持しない。代わりに、チケット化してから 3 日以上完了していないタスクには **「もっと細かく分解しましょう」** のヒントを表示する。 [S3 分解のルール]

### FR-3 チケット（今日やる）と Today ビュー [S3 P4]

- FR-3.1 任意のタスク（または列全体）を「今日のチケット」にできる。同じタスクは同日に 1 枚のみ。
- FR-3.2 Today ビューは当日のチケットを **1 枚ずつのカード（レシート風）** で一覧表示する。上から順に処理することを想定し、並べ替えできる。
- FR-3.3 チケットには親タスク名（カテゴリ見出し）、タイトル、所要時間/タイムボックス、ルーチン由来かどうかを表示する。
- FR-3.4 日付が変わると前日の未完了チケットは「持ち越し候補」として表示し、ワンタップで今日に持ち越し、または破棄できる。
- FR-3.5 チケットの完了は Today ビュー、カラムビューのどちらからでも行える。完了すると元タスクも完了になる（ルーチン・クォータ由来は元タスクを完了にしない）。

### FR-4 完了フィードバック [S1 S2 P2]

- FR-4.1 チケット完了時に **くしゃくしゃに丸まるアニメーション**（カードが縮み、回転し、瓶へ落ちる）を 600ms 以内で再生する。
- FR-4.2 同時に **紙を丸める効果音** を再生する（設定でオフ可）。
- FR-4.3 Android では **触覚フィードバック**（短い振動）を行う（設定でオフ可。非搭載機では何もしない）。
- FR-4.4 連続して完了すると **コンボ表示**（「3 連続！」等）を出す。連続判定は前回完了から 10 分以内。
- FR-4.5 完了は 5 秒以内であれば Undo できる。
- FR-4.6 フィードバックは 100ms 以内に開始する（操作から知覚可能な遅延をなくす）。

### FR-5 透明な瓶 [S2 S3 P2]

- FR-5.1 当日完了したチケットの数だけ **紙玉** を瓶の中に描画する。紙玉は落下して積み上がる。
- FR-5.2 瓶の下に「今日 N ループ」を表示する。
- FR-5.3 瓶は毎日 0 からになるが、過去の瓶（日別の完了数）は統計として保持する。
- FR-5.4 瓶は常時見える位置（デスクトップ/大画面: 右ペイン、スマートフォン: Today タブ上部）に配置する。

### FR-6 ルーチン（曜日別の習慣）と自動準備 [S2 S3 P3 P5]

- FR-6.1 ルーチンは「タイトル、カテゴリ見出し、対象曜日（複数）、順序、所要時間、種類（通常/クォータ）」を持つ。
- FR-6.2 クォータ型は「目標件数」を持ち、チケット上でカウンター（+1 / −1）を操作し、目標到達で完了扱いにできる。 [S3 蓄積タスク]
- FR-6.3 **自動準備**: 設定した「準備時刻」（既定 21:00）以降にアプリを開いたとき、翌日分のルーチンチケットが未生成なら生成する。また、当日分が未生成のままアプリを開いたときは、その場で当日分を生成する。 [S3 前夜準備]
- FR-6.4 生成されたルーチンチケットは Today ビューの先頭に、ルーチンの順序どおり並ぶ（簡単な日課から始めるため、順序はユーザーが編集する）。 [S3 easy wins]
- FR-6.5 ルーチンの一括印刷（当日分）ができる。
- FR-6.6 初回起動時にサンプルルーチン（例: コーヒーを淹れる、2 分ウォームアップ）を提案し、ワンタップで導入できる。

### FR-7 リフォーカス [S3 P7]

- FR-7.1 ショートカット / ボタンで「リフォーカス」ダイアログを開く。「次にやる 3〜5 個」を 1 行 1 件で素早く入力する。
- FR-7.2 入力した各行は即座に今日のチケットとして Today ビューの先頭に追加される（カラムツリー上は「受信箱（Inbox）」プロジェクト直下に作られる）。
- FR-7.3 追加後は 1 枚目を自動的に「実行中」にし、タイムボックスがあればタイマーを開始する。

### FR-8 タイムボックス実行 [S3 P7]

- FR-8.1 チケットを「開始」するとカード上で経過時間を表示する。タイムボックスがあれば残り時間をカウントダウンし、0 で音と表示で通知する。
- FR-8.2 タイムボックス終了時に「完了にする / 延長 5 分 / 分解する」を選べる。

### FR-9 サーマルプリンター印刷 [S2 S3 P4 P5]

対象機器: Irfora 57mm ミニポケットサーマルプリンター（Amazon ASIN B0DNSQ4NWF、型番 LAKJPOS8036W-11、203dpi、
Bluetooth 接続、公式アプリ "Luck Jingle"）。同系統の 58mm ポータブル ESC/POS 機、および一般的なネットワーク
レシートプリンター（Epson TM 系等）も同じ実装で扱う。

- FR-9.1 **接続方式（トランスポート）** を以下から選択できる。
  - (a) **Bluetooth Classic（SPP / RFCOMM, UUID 00001101-0000-1000-8000-00805F9B34FB）**: Android / Chromebook。ペアリング済み機器一覧から選択する。Android 12 以降は `BLUETOOTH_CONNECT` 権限を実行時に要求する。
  - (b) **シリアル COM ポート**: Windows 11。Bluetooth 設定で SPP 機器に割り当てられた仮想 COM ポート（例: `COM5`）を一覧から選択する。
  - (c) **TCP/IP（既定ポート 9100）**: ネットワークプリンター用。Android / Windows 共通。
- FR-9.2 **印刷プロトコル（コマンド体系）** を以下から選択できる。対象機器の既定は「ESC/POS ラスター」。
  - `ESC/POS テキスト`: プリンター内蔵フォントで文字を送る（`ESC @`, `ESC a`, `GS !`, `ESC E`, UTF-8 / Shift_JIS）。日本語フォント内蔵機向け。
  - `ESC/POS ラスター`: アプリ側でチケットをモノクロ画像に描画し `GS v 0` で送る。日本語フォント非内蔵機（対象機器）向け。
  - `ESC/POS ビットイメージ`: 同じ画像を `ESC * 33`（24 ドット密度）で 24 行ずつ送る。`GS v 0` 非対応の旧機向け。
  - `TSPL`: ラベルプリンター向け。`SIZE` / `GAP` / `CLS` / `BITMAP` / `PRINT` で 1 チケット = 1 ラベル。
  - `CPCL`: ラベルプリンター向け。`! 0 200 200 <h> 1` / `EG` / `FORM` / `PRINT`。
- FR-9.3 印刷単位は **1 チケット = 1 枚**。各枚の末尾に「フィード行数（既定 3）」を送り、設定で **カットコマンド（`GS V 66 0`）の有無** を選べる（対象機器はカッター非搭載のため既定オフ）。
- FR-9.4 チケットの印字内容: カテゴリ（親タスク名）を大きく、タイトル、所要時間/タイムボックス/クォータ、日付。ラスター系では画面と同じ描画エンジンで **日本語を含む任意の文字** を描画する。
- FR-9.5 用紙幅: 58mm（384 ドット / テキスト 32 桁）、80mm（576 ドット / 48 桁）。ラベル紙用に **ラベル高さ (mm) と ギャップ (mm)** を設定できる（TSPL/CPCL）。
- FR-9.6 印刷できる対象: (a) 今日のチケット全部、(b) 選択した列の全タスク、(c) 単一タスク、(d) 当日のルーチン。
- FR-9.7 設定画面から **テスト印刷** ができ、接続失敗時はエラー理由を表示する。送信は 5 秒でタイムアウトし、UI を固めない。
- FR-9.8 Bluetooth / シリアル送信は **512 バイト単位に分割** し、間に短い待ち時間を入れて安価な機器のバッファ溢れを防ぐ。
- FR-9.9 印刷したチケットには「印刷済み」マークを付ける。再印刷は可能。
- FR-9.10 印刷濃度（ESC/POS: `GS ( K` / 対象機器互換の `ESC 7`）は v1 では固定とし、設定に持たない。

### FR-10 キーボード主体の高速操作 [S3 P5]

- §8 のショートカットをデスクトップと Chromebook（物理キーボード接続時）で提供する。
- すべての一次操作（作成・分解・移動・完了・チケット化・印刷・リフォーカス）はマウスなしで完結する。

### FR-11 統計 [S2]

- FR-11.1 日別のループ数（完了チケット数）を過去 90 日分バーで表示する。
- FR-11.2 連続日数（1 日 1 ループ以上が続いた日数）を表示する。
- FR-11.3 ルーチンの達成率（過去 30 日）をルーチン別に表示する。

### FR-12 データ管理

- FR-12.1 データはアプリ専用領域の JSON ファイルに保存し、変更のたびに原子的に書き込む。
- FR-12.2 JSON エクスポート/インポート（バックアップ）ができる。
- FR-12.3 データ形式にはスキーマバージョンを持ち、将来のマイグレーションに備える。

### FR-13 設定

- 効果音 ON/OFF、触覚 ON/OFF、準備時刻、プリンター（接続方式、Bluetooth 機器 / COM ポート / ホスト・ポート、プロトコル、用紙幅、文字コード、フィード行数、カット有無、ラベル高さ・ギャップ）、言語（システム追従 / 日本語 / 英語）、完了済みタスクの表示。

## 9. データモデル

```kotlin
Task(id, parentId?, title, order, estimateMin?, timeboxMin?, done, doneAt?, createdAt, updatedAt)
Ticket(id, date /* yyyy-MM-dd */, taskId?, routineId?, category, title, estimateMin?, timeboxMin?,
       quotaTarget?, quotaCount, order, state /* PENDING|RUNNING|DONE */, startedAt?, doneAt?, printedAt?)
Routine(id, title, category, weekdays: Set<DayOfWeek>, order, estimateMin?, timeboxMin?, quotaTarget?, enabled)
Settings(soundEnabled, hapticsEnabled, prepareHour, prepareMinute,
         printer{transport, host, port, bluetoothAddress, bluetoothName, serialPort, protocol, paperWidth, charset,
                 feedLines, cutEnabled, labelHeightMm, labelGapMm},
         language, showCompleted)
DayStat(date, loops)     // 統計用（Ticket から導出可能だが高速化のため保持）
```

- 「受信箱（Inbox）」はルート直下の固定タスク（削除不可）で、リフォーカスからのタスクを受ける。
- 保存ファイル: `kusha-data.json`（`schemaVersion` を含む）。

## 10. 印刷フォーマット

### 10.1 ESC/POS テキスト

```
ESC @                 初期化（Shift_JIS のとき続けて FS & で漢字モード）
ESC a 1               中央揃え
GS ! 0x11             倍角
<CATEGORY>\n
GS ! 0x00
ESC a 0               左揃え
--------------------------------\n
ESC E 1  <TITLE>（用紙幅で折り返し）\n  ESC E 0
[~5min] [BOX 10min] [x10]\n
2026-09-22 (Mon)\n
LF × フィード行数
(GS V 66 0             部分カット: 設定で有効時のみ)
```

### 10.2 ESC/POS ラスター（対象機器の既定）

1. チケットを幅 384 ドット（58mm）の 1bit 画像として描画する（カテゴリ: 太字 大、タイトル: 太字、メタ・日付: 通常、区切り線）。
2. `ESC @` → `ESC a 1` → `GS v 0 0 xL xH yL yH <データ>`（1 バイト = 8 ドット、1 = 黒）→ フィード（→ カット）。
3. 画像高さが 1024 行を超える場合は 256 行ごとに分割して複数の `GS v 0` を送る。

### 10.3 ESC/POS ビットイメージ

`ESC 3 24` で行送りを 24 ドットに設定し、画像を 24 行ごとに `ESC * 33 nL nH <データ>` + `LF` で送る（列優先、縦 3 バイト）。最後に `ESC 2` で行送りを戻す。

### 10.4 TSPL

```
SIZE 58 mm,<h> mm\r\n  GAP <gap> mm,0 mm\r\n  CLS\r\n
BITMAP 0,0,<widthBytes>,<height>,0,<データ: 0 = 黒>\r\n
PRINT 1,1\r\n
```

### 10.5 CPCL

```
! 0 200 200 <height> 1\r\n
EG <widthBytes> <height> 0 0 <16 進データ: 1 = 黒>\r\n
FORM\r\n PRINT\r\n
```

## 11. 受け入れ基準（抜粋）

| ID | 基準 |
|----|------|
| AC-1 | ルート列でタスクを作成し `Tab` で子を作ると、右の列に子が表示され、親行に「1/1」が表示される。 |
| AC-2 | 列見出しの「今日へ」で列内の未完了タスクが全部 Today に 1 枚ずつ現れ、重複しない。 |
| AC-3 | チケットの「完了」を押すと 100ms 以内にアニメーションと音が始まり、瓶の紙玉が 1 個増える。 |
| AC-4 | 火曜のみのルーチンは、火曜の Today にだけ自動生成される。準備時刻を過ぎて開いた月曜夜には翌日（火曜）分が生成される。 |
| AC-5 | クォータ 10 件のチケットは +1 を 10 回押すと完了になる。 |
| AC-6 | プリンター未接続（Bluetooth / COM / TCP いずれも）で印刷すると 5 秒以内にエラーが表示され、アプリは固まらない。 |
| AC-7 | ESC/POS テキストのバイト列は §10.1 の順序で、カット有効時のみチケットごとに `GS V 66 0` を含む（単体テスト）。ラスター/ビットイメージ/TSPL/CPCL の各エンコーダは同じ 1bit 画像から §10.2〜10.5 のヘッダとデータ長を正しく生成する（単体テスト）。 |
| AC-8 | 幅 840dp 以上では 3 ペイン、未満では下部タブ構成になる。 |
| AC-9 | データファイルを削除して起動すると、初期状態（Inbox のみ）で起動しクラッシュしない。 |
| AC-10 | Chromebook でタッチ非搭載でもインストール可能（マニフェストの単体検証）。 |

## 12. スコープ外（v1）

- クラウド同期、複数端末間の同期、アカウント。
- USB 接続のプリンター、BLE（Bluetooth Low Energy）のみの機器（例: GB01 系「キャットプリンター」）。
- iOS / macOS / Linux 向け配布（コードは共通だが配布物は用意しない）。
- 通知・リマインダー（ADHD 向けには有効だが、記事の手法の範囲外）。
